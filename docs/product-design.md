> 版本：v1.0（2026-09-05 拷问会话定稿） · 配套文档：[CONTEXT.md](../CONTEXT.md) · [ADR 0001 押金托管](./adr/0001-escrow-qualification.md) · [日程](./schedule.md)

## 1. 产品概述

**一句话定位**：基于 Monad 的链上可信抽奖平台 —— 用智能合约托管 + 可验证随机数，彻底消除抽奖场景中"主办方作弊"的信任问题。

**解决的问题**：传统抽奖（线上活动、线下活动、社区营销）中，参与者无法验证三件事：
1. 中奖名单是不是真的（没中奖的人是真的参与了吗？）
2. 开奖过程是不是被操纵的（主办方想给谁就给谁？）
3. 承诺的奖品真的会发吗？

本产品把这三件事全部变成**链上可验证**：资格名单在链上、随机数可验证、派奖由合约执行。

## 2. 核心机制（用户旅程）

```
参与者                                  合约                       主办方/赞助方
   │                                     │                             │
   │  ① register() + 10 MOD 押金          │                             │
   ├────────────────────────────────────>│ 资格名单 +1，押金入托管       │
   │                                     │                             │  ② fundPrizePool() 注入奖金
   │  ③ 等待锁仓期（默认 3 天）            │ 押金锁定，不可取回           │
   │                                     │                             │
   │  ④ 到期后任何人触发 draw(userSeed)   │                             │
   ├────────────────────────────────────>│ 请求 Pyth Entropy            │
   │                                     │ <── 随机数回调 ──            │
   │  ⑤ 链上公布中奖者                    │ random % 参与人数 → 中奖者    │
   │                                     │                             │
   │  ⑥ claimDeposit() 领回 10 MOD        │      中奖者 claimPrize() 领奖金│
   │  （未中奖押金 100% 退回）             │                             │
```

关键设计决策（已拷问确认）：

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 资格验证 | **押金托管进合约**，锁仓 3 天（参数化） | 完全链上可验证、天然防女巫、无链下信任假设，详见 [ADR 0001](./adr/0001-escrow-qualification.md) |
| 参与登记 | **链上注册交易**（`register()` 附带押金），不支持网页填地址 | 一笔交易同时完成所有权证明 + 托管 + 上名单 |
| 防女巫 | 一地址 = 一份押金 = 一次资格 | 押金有真实成本，刷号经济上不划算 |
| 随机数 | **Pyth Entropy VRF**（Monad testnet 已部署） | 可验证公平，且支持请求方自带种子 |
| 开奖触发 | **任何人可触发**（Permissionless），条件：到期 + 名单非空 | 无需信任项目方；Monad gas 便宜，触发成本可忽略 |
| 奖池 | **赞助方单独注入**，与押金严格分离 | 押金是资格凭证不是门票，开奖后 100% 退回 |
| 中途取回 | **锁仓期内禁止**，合约不提供取回函数 | "维持 3 天任务"定义清晰；pull 模式领回 |

## 3. 两种开奖形式

### 3.1 定时开奖
- 部署合约时设定 `drawTime` 与 `lockPeriod`（默认 3 天）。
- 到期后任何人可调用 `draw(userSeed)` 触发，`userSeed` 由项目方预先公布（如写在活动页面上），公开承诺、不可抵赖。
- 场景：线上社区活动、周期性营销抽奖。

### 3.2 现场开奖（差异化亮点）
- 现场观众**扫码**打开参与页面，各自产生随机数（输入/摇手机）。
- 前端将所有观众熵 hash 合并为 `userSeed`，由现场任意一名持钱包者（或主持人钱包）发起 `draw(userSeed)` 交易。
- Pyth 验证者熵与现场熵混合 → **"把现场变成随机数源"**，观众真实参与了开奖过程。
- 场景：黑客松颁奖、线下 meetup、展会抽奖。

两种形式共用同一随机数链路（Pyth Entropy），合约逻辑完全一致，仅 `userSeed` 来源不同。

### 3.3 线下活动准入：防远程薅羊毛（详见 [ADR 0002](./adr/0002-on-site-admission-signature.md)）

**威胁**：`register()` 若完全无许可，全球任何地址（testnet 押金零成本）都能入围，线下活动定向的赞助奖池会被远程羊毛党稀释——奖金 > 押金时薅羊毛是正期望收益。

**方案：签发者准入签名（同合约双模式）**

```
参与者到场 → 签到处核验门票/胸牌（物理在场）
          → 工作人员工具页对参与者地址 ECDSA 签名（绑定地址+活动ID+有效期）
          → 生成二维码回传给参与者
          → 参与者扫码，自行发起 register(sig) + 10 MOD 押金
          → 合约 ecrecover 验签通过 → 入围
```

- **合约层**：构造函数接收 `issuer` 地址。非零 = 线下模式（注册验签），零地址 = 线上无许可模式。一套代码，两种产品形态。
- **威胁缓解对照**：

| 攻击手法 | 缓解 |
|----------|------|
| 远程直接 register() | 验签失败，交易回滚 |
| 窃取/转发他人签名 | 签名绑定被签地址，对其他地址无效 |
| 现场公布统一口令 | 不使用口令；签名不经过公开信道（二维码当面回传） |
| 工作人员给场外朋友签名 | 有界信任：与现实中检票员放熟人进场同级；签名记录链上可事后审计 |
| 一人多钱包刷票 | 签到处人工核验"一人一签"，合约层不做限制 |
| 签发者密钥泄露 | 密钥无提款权限，最大损失 = 若干张无效准入票；作废活动重启即可 |

**残余信任声明**：线下模式的准入信任 = 线下活动本就存在的检票环节，未新增信任假设；签发者无法触碰押金与奖池。

## 4. 随机数设计

- 服务：**Pyth Entropy**（Monad testnet 合约 `0x36825bf3Fbdf5a29E2d5148bfe7Dcf7B5639e320`）。
- 流程：`draw(userSeed)` → 合约调用 Entropy `request`（附带 userSeed，缴纳请求费）→ Pyth 验证者返回 `providerConfirmedRandomNumber` → 合约回调中计算 `winnerIndex = random % participants.length`。
- 公平性：随机数 = 验证者熵 + 用户种子共同决定，任何单方（项目方、验证者、观众）都无法独立操纵结果，且过程链上可审计。
- 请求费：触发者垫付，开奖成功后从奖池中返还（金额极小）。

## 5. 信任模型对比（评委核心关注）

| 信任风险 | 传统抽奖 | Monad Blitz |
|----------|----------|-------------|
| 参与者真实性 | 名单不透明，可凭空造假 | 链上注册事件，一地址一份押金 |
| 主办方操纵结果 | 黑箱开奖，无法验证 | Pyth Entropy 可验证随机数，任何单方无法操纵 |
| 奖品承诺 | 口头发钱，可能赖账 | 奖金预先锁入合约，合约强制派发 |
| 押金安全 | 无此概念 | 合约托管，到期 100% 退回，锁仓期内谁也拿不走 |
| 开奖执行 | 主办方说了算 | 到期后任何人可触发，无准入 |

**残余信任假设**（诚实声明）：Pyth 验证者网络（多数诚实）、Monad 共识层；线下活动模式另含签发者准入信任（与检票同级，无资金权限，见 3.3 节）。除此之外无项目方特权（合约无 owner 提款函数，仅保留参数设置在部署时固定）。

## 6. 合约设计草案（Lottery.sol）

```
状态
  participants: address[]          // 注册名单（有序，用于随机索引）
  registered: mapping(addr => bool)
  drawTime / lockPeriod / winnerCount   // 部署时固定参数
  status: Open → Drawing → Drawn
  winner: address                  // 默认 1 名
  prizePool: uint256               // 赞助方注入，与押金分离

核心函数
  register() payable               // msg.value == 10 MOD，push 名单
  draw(bytes32 userSeed)           // require 到期 + 名单非空 + 未开奖；请求 Entropy
  entropyCallback(...)             // VRF 回调：random % n → 中奖者，状态 → Drawn
  claimDeposit()                   // 开奖后，参与者领回 10 MOD（pull 模式）
  claimPrize()                     // 中奖者领奖池奖金
  fundPrizePool() payable          // 赞助方注入奖金

事件
  Registered(addr) / DrawRequested(seq, userSeed) /
  WinnerSelected(winner, random) / DepositClaimed(addr) / PrizeClaimed(addr)
```

要点：押金账本与奖池账本分离核算；无 owner 提款函数；锁仓期内无任何取回路径。

## 7. 边界情形与风险清单（拷问产出）

| # | 风险/边界 | 应对 |
|---|-----------|------|
| 1 | **Monad 10 MON 底金规则与押金冲突**：账户余额过低的用户存入 10 MOD 后，交易可能因 ending balance 低于底金而回滚（除非触发 emptying exception） | 参与指引要求钱包余额 ≥ 20 MOD；**11:00 环境搭建阶段必须实测 12 MOD 存入场景**，确认 emptying exception 是否覆盖 |
| 2 | Pyth Entropy 回调失败/延迟 | draw 状态机允许在超时后重新 `draw()` 请求（重新缴费），随机数未产生前状态保持 Drawing |
| 3 | 名单为空时到期 | draw() revert，任何人可在有新注册后再触发；赞助方奖金不受影响 |
| 4 | 中奖者/参与者永不领回 | 资金安全留在合约中可随时 claim（pull 模式无资金损失），多期化后在后续版本增加超时回收 |
| 5 | 低余额账户交易频率限制（<10 MON 每 3 区块 1 笔） | 对本产品无实质影响，注册/领回均为单笔操作 |
| 6 | 演示等待不了 3 天 | `lockPeriod`/`drawTime` 为部署参数，演示合约设为分钟级；正式使用设为 3 天 |

## 8. 演示脚本（对齐 schedule.md）

> 原则（来自日程 7.1）：**避免现场输入** —— 所有钱包提前准备、交易提前彩排。

1. **预准备**：合约部署（锁仓 3 分钟版）、4 个预充值测试钱包（≥20 MOD）、赞助方钱包注入奖池、3 个钱包提前完成注册。
2. **录屏叙事线**：钱包 A 新注册（展示 10 MOD 入托管 + 链上名单更新）→ 展示押金锁定（尝试取回被拒）→ 到期 → 触发 draw（展示公开 userSeed）→ Pyth 回调 → 链上公布中奖者 → 未中奖者领回押金（余额回归）→ 中奖者领取奖金。
3. **现场集熵演示**：多浏览器窗口模拟 3 名观众扫码产熵 → 前端 hash 合并 → 一键开奖。
4. **PPT 讲述重点**：信任模型对比表（第 5 节）+ "把现场变成随机数源"。

## 9. 评委关注点映射

- **创新性**：观众扫码集熵参与开奖，把线下场景变成链上随机数源（非套壳 VRF demo）。
- **技术难度**：Monad 原生部署 + Pyth Entropy 异步回调集成 + 押金/奖池双账本。
- **Monad 特性利用**：低 gas 使"任何人可触发开奖"经济可行（以太坊上触发费高得多）；高 TPS 支撑现场大量观众同时扫码注册。
- **商业潜力**：活动营销、社区运营、展会互动的通用信任基础设施；未来可扩展门票分成模式。

## 10. 未来规划（不在本次黑客松范围）

1. 多期抽奖循环 + 门票分成模式（押金退回 + 小额 ticket）。
2. 资产口径扩展：支持 ERC-20/NFT 持仓证明作为额外加权资格。
3. 超时无人认领资金的回收机制。
4. 中奖人数 > 1 与按权重派奖。
