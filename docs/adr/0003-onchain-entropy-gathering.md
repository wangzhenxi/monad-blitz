# ADR 0003: 现场集熵采用链上提交聚合

**状态**: 已接受（2026-09-05）

## 上下文

现场开奖要求把观众各自的熵汇聚为 `draw(userSeed)` 的触发参数。产品文档只定义了"前端将所有观众熵 hash 合并"，聚合通道未定。备选路径：

1. **链上提交聚合**：合约提供 `submitEntropy(bytes32)`，观众各发一笔交易提交熵，合约以 O(1) storage 维护累积哈希（熵根），开奖时校验或审计
2. **链下 API 聚合**：Next.js API route 收集各观众熵，触发者拉取聚合结果
3. **本地多窗口聚合**：仅演示可用，触发者浏览器内聚合

## 决策

采用**方案 1：链上提交聚合**。合约维护 `entropyRoot`（每次提交后 `entropyRoot = keccak256(entropyRoot, e)` 累积），`submitEntropy` 仅限已注册地址调用。当 `entropyRoot != 0` 时 `draw(userSeed)` 强制校验 `userSeed == entropyRoot`（现场模式语义）；为零时接受任意 userSeed（定时模式的公开承诺语义）。两种产品形态由熵根是否非零自动区分。

## 后果

- ✅ 聚合过程完全链上可审计，与"消除信任问题"的产品定位一致
- ✅ 无后端组件：不需要服务器存储/转发观众熵，部署面最小
- ✅ 观众的熵提交交易本身即是参与感与演示素材
- ✅ 触发者无法替换 seed（熵根非零时合约强制校验），堵住"触发者偷换 userSeed"的审计缺口
- ⚠️ 每名观众多一笔交易（Monad gas 极低，可接受）
- ⚠️ 定时模式下若有人恶意提交熵，熵根非零会强制校验、使项目方预公布 seed 失效——缓解：submitEntropy 限已注册地址（需先押 10 MOD），且活动页不向定时模式用户提供集熵入口；被破坏可从链上事件发现
