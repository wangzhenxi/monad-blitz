# ADR 0002: 线下活动采用签发者准入签名防薅羊毛

**状态**: 已接受（2026-09-05）

## 上下文

产品支持线下现场抽奖形态，赞助方奖池定向服务现场参与者。但当前 `register()` 是 Permissionless 的：全球任何地址只要有 ≥20 MOD（testnet 免费领取）即可注册入围，奖金 > 押金时远程薅羊毛为正期望收益，奖池将被稀释。

"物理在场"无法由链上原生验证，备选路径：
1. **签发者准入签名**：主办方工作人员在签到处核验在场后对地址 ECDSA 签名，合约验签后接受注册
2. **纯经济门槛**：提高押金/降低奖金使薅羊毛无利可图
3. **地理围栏/时空证明**：IP/GPS/基站证明

## 决策

采用**方案 1**，并以**同合约双模式**落地：构造函数接收 `issuer` 地址 —— 非零即线下模式（`register()` 必须附有效准入签名），零地址即线上无许可模式。凭据形态为**逐人签名 + 扫码回传**：工作人员工具页对参与者地址签名（绑定地址 + 活动 ID + 有效期），生成二维码由参与者扫码后自行发起注册交易。

## 后果

- ✅ 信任假设与线下活动现状对齐：准入本就由看门人（检票员）控制，上链不新增信任
- ✅ 签名绑定地址，泄露无效；签发者密钥无提款权限，最大损失 = 多签几张准入票
- ✅ 合约增量仅一行 ecrecover + 一个构造参数，满足当天交付
- ⚠️ 引入有界信任假设：签发者可能监守自盗（给场外朋友签名）—— 与现实中检票员放熟人进场同级，可接受并通过签名记录事后审计
- ⚠️ 拒绝路径明确：一人多钱包现场刷票由人工核验兜底（一人一签），合约层不做限制
- ❌ 方案 2 在 testnet 场景下失效（押金零成本）；方案 3 全部可伪造且需链下基建，均弃用
